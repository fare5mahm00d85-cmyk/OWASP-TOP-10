# Broken Access Control — Cheat Sheet

## ما هو Access Control؟

هو النظام المسؤول عن تحديد **من يمكنه الوصول إلى ماذا، وما الذي يمكنه فعله** داخل التطبيق.

---

## Authentication vs Authorization

### Authentication (المصادقة)

**السؤال:** أنت مين؟

- التحقق من هوية المستخدم.
    
- يتم باستخدام Username + Password أو أي وسيلة تسجيل دخول.
    

**مثال:**

```
Username: ahmed
Password: 123456
```

إذا كانت البيانات صحيحة → يتم تسجيل الدخول.

---

### Authorization (التفويض)

**السؤال:** ماذا يحق لك أن تفعل؟

- يحدد صلاحيات المستخدم بعد تسجيل الدخول.
    
- مثل:
    
    - دخول لوحة الإدارة.
        
    - حذف مستخدم.
        
    - تعديل بيانات.
        
    - مشاهدة ملفات.
        

---

## Broken Access Control

هو **فشل التطبيق في التحقق من صلاحيات المستخدم**، مما يسمح له بالوصول إلى صفحات أو بيانات أو تنفيذ عمليات غير مصرح بها.

---

# الأنواع الأساسية

## 1) Vertical Access Control

**الوصف:** مستخدم يحصل على صلاحيات أعلى من مستواه.

**مثال:**

```
User → Admin
```

أو الوصول إلى:

```
/admin
/admin-panel
```

---

## 2) Horizontal Access Control

**الوصف:** مستخدم يصل إلى بيانات مستخدم آخر بنفس مستوى الصلاحيات.

**مثال:**

```
/profile?id=10
```

يتم تغييرها إلى:

```
/profile?id=11
```

إذا ظهرت بيانات المستخدم الآخر ⇒ توجد ثغرة.

---

## 3) Context-Dependent Access Control

**الوصف:** تنفيذ عملية في وقت أو حالة لا يجب أن تكون متاحة.

**مثال:**

- حذف Order بعد أن أصبح Delivered.
    
- تعديل طلب بعد انتهاء المهلة.
    

---

# أماكن البحث عن الثغرة

- صفحات الإدارة.
    
- صفحات تعديل المستخدمين.
    
- صفحات حذف المستخدمين.
    
- الفواتير.
    
- الملفات.
    
- الحسابات.
    
- الـ APIs.
    
- أي Parameter يحتوي على:
    

```
id=
user=
account=
order=
invoice=
file=
```

---

# طريقة التفكير أثناء الاختبار

اسأل نفسك دائمًا:

- هل أستطيع الوصول لصفحة ليست من حقي؟
    
- هل أستطيع رؤية بيانات مستخدم آخر؟
    
- هل أستطيع تعديل بيانات مستخدم آخر؟
    
- هل أستطيع حذف شيء لا أملكه؟
    
- هل التحقق من الصلاحيات يتم على **الخادم (Server)** أم يعتمد فقط على الواجهة (Client)؟
    

---

# ملخص سريع

- **Authentication** = التحقق من الهوية.
    
- **Authorization** = تحديد الصلاحيات.
    
- **Broken Access Control** = فشل التحقق من الصلاحيات.
    
- **Vertical** = الوصول لصلاحيات أعلى.
    
- **Horizontal** = الوصول لبيانات مستخدم آخر.
    
- **Context-Dependent** = تنفيذ عملية في وقت أو حالة غير مسموح بها.
