# 1) Input Validation ⭐⭐⭐⭐⭐

## ما هو؟

هو **التحقق من صحة البيانات التي يدخلها المستخدم قبل معالجتها أو تخزينها**.

بمعنى أن السيرفر أو التطبيق يتأكد أن البيانات بالشكل المتوقع.

---

## لماذا نستخدمه؟

لمنع إدخال بيانات غير صحيحة أو ضارة.

---

## مثال

يوجد حقل للعمر.

المتوقع

```
25
```

إذا كتب المستخدم

```
abc
```

أو

```
<script>
```

يقوم Input Validation برفضها إذا كان الحقل يقبل أرقامًا فقط.

---

## مثال JavaScript

```
let age = "25";

if(!isNaN(age)){
    console.log("Valid");
}else{
    console.log("Invalid");
}
```

---

## أنواع Input Validation

### 1- Client-side Validation

يتم داخل المتصفح.

مثال

```
<input type="number">
```

أو

```
<input required>
```

❌ غير كافٍ للحماية لأنه يمكن تجاوزه.

---

### 2- Server-side Validation ⭐⭐⭐⭐⭐

يتم داخل السيرفر.

حتى لو تجاوز المهاجم التحقق في المتصفح، يقوم السيرفر بإعادة التحقق.

✅ هو الأهم.

---

## أمثلة

يسمح فقط بالأرقام

```
12345
```

يسمح فقط بالبريد الإلكتروني

```
user@gmail.com
```

يسمح فقط بالحروف

```
Ahmed
```

---

## هل يمنع XSS؟

يساعد في تقليل المخاطر، لكنه **ليس كافيًا وحده**.

---

# 2) Output Encoding ⭐⭐⭐⭐⭐

## ما هو؟

هو **تحويل البيانات قبل عرضها في الصفحة حتى لا يفسرها المتصفح كـ HTML أو JavaScript**.

---

## مثال

المستخدم كتب

```
<script>alert(1)</script>
```

بدلًا من عرضه كما هو

يقوم التطبيق بتحويله إلى

```
&lt;script&gt;alert(1)&lt;/script&gt;
```

فيظهر كنص عادي.

---

## مثال

قبل

```
<p><script></p>
```

بعد

```
<p>&lt;script&gt;</p>
```

---

## لماذا هو مهم؟

لأنه يمنع المتصفح من تنفيذ الكود.

---

## الفرق بين Input Validation وOutput Encoding

|Input Validation|Output Encoding|
|---|---|
|يفحص البيانات عند الإدخال|يحول البيانات عند العرض|
|يمنع البيانات غير الصحيحة|يمنع تنفيذها داخل الصفحة|
|يحدث قبل التخزين|يحدث قبل الإظهار|

---

# 3) Sanitization ⭐⭐⭐⭐⭐

## ما هو؟

هو **تنظيف البيانات** بإزالة أو السماح فقط بعناصر معينة قبل عرضها أو تخزينها.

---

## مثال

المستخدم كتب

```
<b>Hello</b>
<script>alert(1)</script>
```

بعد Sanitization

```
<b>Hello</b>
```

تم حذف

```
<script>
```

وبقيت العناصر المسموح بها.

---

## مثال آخر

إذا كان الموقع يسمح ببعض تنسيقات HTML (مثل `<b>` و`<i>`)، يمكنه إزالة العناصر الخطيرة مثل `<script>` أو خصائص الأحداث مثل `onclick`.

---

## الفرق بين Encoding و Sanitization

|Encoding|Sanitization|
|---|---|
|يحول الأحرف إلى Entities|يزيل أو ينظف المحتوى غير المسموح|
|يحافظ على النص كما هو|قد يحذف أجزاء من الإدخال|

---

# 4) CSP (Content Security Policy) ⭐⭐⭐⭐⭐

## ما هو؟

هو **سياسة أمنية يرسلها السيرفر عبر HTTP Header لتحديد ما الذي يسمح للمتصفح بتحميله أو تشغيله**.

---

## أين يوجد؟

داخل Response Header

```
Content-Security-Policy:
default-src 'self'
```

---

## ماذا يفعل؟

يمكنه تحديد:

- من أين يتم تحميل JavaScript.
- من أين يتم تحميل الصور.
- من أين يتم تحميل CSS.
- هل يسمح بـ Inline Script أم لا.

---

## مثال

```
Content-Security-Policy:

default-src 'self'
```

يعني

يسمح فقط بالملفات القادمة من نفس الموقع.

---

## مثال آخر

```
Content-Security-Policy:

script-src 'self'
```

يسمح فقط بتشغيل JavaScript من نفس الموقع.

---

## لماذا هو مهم في XSS؟

إذا كان الـ CSP مضبوطًا بشكل جيد، فقد يمنع تشغيل بعض أنواع السكربتات حتى لو تمكن المهاجم من إدخالها.

> **مهم:** وجود CSP لا يعني أن الموقع غير قابل للاستغلال، لكنه طبقة دفاع إضافية تعتمد فعاليتها على كيفية إعدادها.

---

## أين أراه؟

في Burp

```
Response

↓

Headers

↓

Content-Security-Policy
```

أو في DevTools → **Network** → **Headers**.

---

# 5) HttpOnly Cookie ⭐⭐⭐⭐⭐

## ما هو؟

خاصية تضاف إلى الـ Cookie.

---

مثال

```
Set-Cookie:

session=abc123;

HttpOnly
```

---

## ماذا تفعل؟

تمنع JavaScript من قراءة الـ Cookie.

---

بدون HttpOnly

```
console.log(document.cookie);
```

الناتج

```
session=abc123
```

---

مع HttpOnly

```
console.log(document.cookie);
```

لن تظهر هذه الـ Cookie.

---

## لماذا هي مهمة؟

إذا وُجدت ثغرة XSS، فإن JavaScript لن يستطيع قراءة الـ Cookie الموسومة بـ `HttpOnly`.

---

## أين أراها؟

في

**DevTools**

↓

Application

↓

Cookies

↓

ستجد عمودًا باسم

```
HttpOnly
```

أو في Burp داخل:

```
Set-Cookie:

HttpOnly
```

---

# مقارنة سريعة

|المفهوم|ماذا يفعل؟|
|---|---|
|**Input Validation**|التحقق من صحة البيانات عند الإدخال|
|**Output Encoding**|تحويل البيانات قبل عرضها|
|**Sanitization**|إزالة أو تنظيف المحتوى غير المسموح|
|**CSP**|تحديد ما الذي يسمح للمتصفح بتشغيله أو تحميله|
|**HttpOnly**|منع JavaScript من قراءة بعض الـ Cookies|

---

# كيف تعمل هذه الحمايات معًا؟

```
المستخدم يرسل البيانات
          │
          ▼
Input Validation
(التحقق من صحة الإدخال)
          │
          ▼
تخزين البيانات
          │
          ▼
Sanitization (إذا لزم الأمر)
(تنظيف المحتوى المسموح)
          │
          ▼
Output Encoding
(ترميز البيانات قبل عرضها)
          │
          ▼
المتصفح يعرض الصفحة
          │
          ▼
CSP يقيّد تحميل وتشغيل الموارد
          │
          ▼
HttpOnly يحمي بعض الـ Cookies من الوصول عبر JavaScript
```

---

# 🎯 ملخص للحفظ

|المفهوم|الأهمية|دوره ضد XSS|
|---|---|---|
|**Input Validation**|⭐⭐⭐⭐⭐|تقليل الإدخالات غير الصحيحة أو غير المتوقعة|
|**Output Encoding**|⭐⭐⭐⭐⭐|منع المتصفح من تفسير البيانات ككود|
|**Sanitization**|⭐⭐⭐⭐⭐|إزالة أو تنظيف المحتوى الخطير|
|**CSP**|⭐⭐⭐⭐⭐|طبقة دفاع إضافية لتقييد تشغيل السكربتات|
|**HttpOnly Cookie**|⭐⭐⭐⭐⭐|يمنع JavaScript من قراءة بعض الـ Cookies|

> **احفظ القاعدة الذهبية في XSS:**
> 
> - **Input Validation** = افحص ما يدخل.
> - **Sanitization** = نظّف ما يُسمح به.
> - **Output Encoding** = رمّز ما سيُعرض.
> - **CSP** = قيّد ما يمكن للمتصفح تشغيله.
> - **HttpOnly** = امنع JavaScript من قراءة الـ Cookies الحساسة.
