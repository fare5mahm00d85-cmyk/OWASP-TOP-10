# مقدمة

أحد أكثر أسباب فشل اختبار XSS هو عدم فهم الـ Encoding.

قد تدخل بيانات معينة، ثم ترى أنها ظهرت بشكل مختلف داخل الصفحة.

مثلاً بدلاً من أن ترى:

```
<
```

ترى:

```
&lt;
```

أو

```
&#60;
```

أو

```
%3C
```

وهنا يبدأ السؤال:

> لماذا تغيرت البيانات؟

الإجابة غالبًا هي:

```
Encoding
```

---

# ما هو Encoding؟

الـ Encoding هو:

> **تحويل البيانات من شكل إلى شكل آخر حتى يمكن تخزينها أو نقلها أو عرضها بأمان، مع إمكانية استرجاعها مرة أخرى.**

إذن Encoding لا يهدف إلى إخفاء البيانات.

ولا يهدف إلى تشفيرها.

ولا يهدف إلى حذفها.

هو فقط يغير طريقة تمثيلها.

---

# مثال بسيط

الحرف

```
<
```

يمكن تمثيله كالتالي:

```
&lt;
```

أو

```
&#60;
```

أو

```
&#x3C;
```

كلهم يمثلون نفس الحرف.

---

# لماذا نستخدم Encoding؟

عدة أسباب:

- نقل البيانات عبر الإنترنت.
- عرض البيانات بأمان.
- منع تفسير بعض الرموز كأوامر.
- تمثيل الحروف الخاصة.

# أولاً

# HTML Encoding

الأكثر أهمية في XSS.

---

## لماذا؟

لأن HTML يحتوي على رموز خاصة.

مثل

```
<
>
&
"
'
```

لو لم تتم معالجتها عند الحاجة، قد يفسرها المتصفح كجزء من الصفحة.

---

## أشهر HTML Entities

|Character|Entity|
|---|---|
|`<`|`&lt;`|
|`>`|`&gt;`|
|`&`|`&amp;`|
|`"`|`&quot;`|
|`'`|`&#39;` أو `&apos;`|

---

# مثال

إذا أراد الموقع عرض النص:

```
2 < 5
```

بدون Encoding

قد يفسر `<` كبداية وسم.

لذلك يتم تحويله إلى:

```
2 &lt; 5
```

ثم يعرضه المتصفح كنص.

---

# Encoding و XSS

في تطبيقات الويب، استخدام **Output Encoding** في المكان المناسب يساعد على منع المتصفح من تفسير مدخلات المستخدم كجزء من الصفحة، ويجعلها تُعرض كنص.

لكن يجب أن يكون الـ Encoding مناسبًا للـ **Context** (HTML، Attribute، JavaScript، URL...)، لأن لكل Context قواعد مختلفة.

# أخطاء شائعة

❌ الاعتقاد أن Base64 = Encryption.

❌ الاعتقاد أن Encoding يحذف البيانات.

❌ الاعتقاد أن كل أنواع Encoding متشابهة.

❌ الخلط بين URL Encoding وHTML Encoding.

❌ استخدام Output Encoding غير مناسب للـ Context.
