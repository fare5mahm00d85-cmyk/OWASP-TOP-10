# ما هو XSS؟

XSS اختصار لـ

```
Cross-Site Scripting
```

وهو نوع من ثغرات تطبيقات الويب يحدث عندما يسمح الموقع للمهاجم بإدخال بيانات تحتوي على **JavaScript** ثم يعرضها للمستخدم بدون معالجة أو ترميز مناسب، فيقوم المتصفح بتنفيذ هذا الكود.

ببساطة:

```
User Input
      │
      ▼
Website
      │
(بدون حماية)
      ▼
Browser
      │
ينفذ JavaScript
```

الفكرة الأساسية:

> المتصفح لا يعرف إذا كان JavaScript جاء من مطور الموقع أو من مهاجم، طالما وصل داخل صفحة بطريقة تجعل المتصفح يعتبره كودًا صالحًا للتنفيذ.

---

# لماذا تعتبر XSS خطيرة؟

لأن الكود يعمل داخل متصفح الضحية وبصلاحيات الموقع نفسه (ضمن حدود سياسات المتصفح)، ويمكن أن يؤدي إلى:

- سرقة بيانات من الصفحة.
- تنفيذ عمليات باسم المستخدم إذا كانت الجلسة ما زالت صالحة.
- تعديل محتوى الصفحة.
- خداع المستخدم بواجهات مزيفة.
- قراءة بعض البيانات غير المحمية داخل الصفحة.

> ملاحظة: الكوكيز التي عليها `HttpOnly` لا يمكن قراءتها بواسطة JavaScript.

عندما تكتب

```
https://example.com
```

تحدث الخطوات التالية:

```
Browser
    │
HTTP Request
    │
Server
    │
HTTP Response
    │
HTML + CSS + JS
    │
Browser
    │
Render
```

أي أن الخادم يعيد ملفات الصفحة، ثم يبدأ المتصفح في تفسيرها وعرضها.

# ما هو DOM؟

DOM

اختصار

```
Document Object Model
```

وهو تمثيل الصفحة داخل ذاكرة المتصفح.

بدلاً من التعامل مع النص

```
<h1>Hello</h1>
```

يتعامل JavaScript مع

```
Object
```

له خصائص ودوال.

مثلاً

```
document.querySelector("h1")
```

يرجع عنصر

```
H1
```

ثم يمكن تعديله.

---

مثال

```
document.querySelector("h1").textContent="Welcome";
```

النتيجة

قبل

```
Hello
```

بعد

```
Welcome
```

# لماذا DOM مهم في XSS؟

لأن معظم ثغرات

```
DOM XSS
```

تحدث عندما يقرأ JavaScript بيانات من المستخدم ثم يضعها داخل الـ DOM بطريقة غير آمنة.

# JavaScript Engine

كل متصفح يحتوي على محرك JavaScript.

أمثلة:

- Chrome → V8
- Firefox → SpiderMonkey
- Safari → JavaScriptCore

وظيفته:

- قراءة JavaScript.
- تحويله إلى تعليمات قابلة للتنفيذ.
- تشغيل الكود.

# لماذا JavaScript هي المستخدمة في XSS؟

لأن HTML وحدها لا تنفذ أوامر.

أما JavaScript فتستطيع:

- تعديل الصفحة.
- التعامل مع المستخدم.
- إرسال طلبات إلى نفس الموقع.
- قراءة أجزاء من الصفحة.
- استخدام واجهات المتصفح.

# كيف يفرق المتصفح بين النص والكود؟

إذا كتبت

```
Hello
```

سيعرض

```
Hello
```

أما إذا كتبت

```
<script>

alert(1)

</script>
```

فسيفهم أن ما بين `<script>` هو JavaScript ويقوم بتنفيذه.

# User Input

أي بيانات يدخلها المستخدم.

مثل

- Search
- Comment
- Username

- URL Parameter
- Header
- Cookie

كلها تعتبر

```
User Controlled Input
```

# Source

هو المكان الذي تأتي منه البيانات.

أمثلة:

```
location.search
```

```
location.hash
```

```
document.URL
```

```
document.cookie
```

```
localStorage
```

---

# Sink

هو المكان الذي توضع فيه البيانات.

مثال آمن:

```
element.textContent=userInput;
```

يعرض النص كما هو.

مثال غير آمن:

```
element.innerHTML=userInput;
```

إذا احتوى الإدخال على HTML أو JavaScript، فقد يتم تفسيره بدلًا من عرضه كنص.

---

# الفرق بين textContent و innerHTML

مثال

```
textContent="<b>Hello</b>";
```

النتيجة

```
<b>Hello</b>
```

يظهر كنص.

---

أما

```
innerHTML="<b>Hello</b>";
```

النتيجة

```
Hello
```

بخط عريض لأن المتصفح فسر الوسوم.

---

# Input Validation

تعني التحقق من أن المدخلات مطابقة لما هو متوقع.

مثال:

إذا كان الحقل يقبل عمرًا، فلا ينبغي قبول أحرف أو أكواد HTML.

---

# Output Encoding

تعني ترميز البيانات قبل عرضها.

مثلاً

بدلاً من

```
<
```

تصبح

```
&lt;
```

وبالتالي تُعرض كنص ولا تُفسر كوسم HTML.

---

# Sanitization

تعني إزالة أو تعديل العناصر الخطرة من المحتوى مع السماح بالمحتوى المسموح.

مثلاً قد تسمح بعناصر تنسيق مثل `<b>` و`<i>`، لكن تمنع عناصر أو خصائص قد تؤدي إلى تنفيذ JavaScript.

---

# Encoding vs Sanitization

Encoding

```
يعرض البيانات كنص
```

Sanitization

```
يحاول تنظيف المحتوى مع الإبقاء على الأجزاء المسموح بها
```

# Cookies

الكوكي هي بيانات صغيرة يخزنها المتصفح ويرسلها تلقائيًا إلى نفس الموقع مع الطلبات المناسبة.

قد تحتوي على:

- Session ID
- Language
- Theme
- تفضيلات المستخدم

---

# Session

بعد تسجيل الدخول، ينشئ الخادم جلسة (Session) ويرتبط بها معرف يتم تخزينه غالبًا في Cookie.

في كل طلب لاحق:

```
Browser

↓

Session Cookie

↓

Server

↓

يعرف المستخدم
```

---

# HttpOnly Cookie

إذا كانت الكوكي تحمل الخاصية:

```
HttpOnly
```

فلن يستطيع JavaScript قراءتها باستخدام:

```
document.cookie
```

وهذا يقلل من بعض آثار XSS، لكنه لا يمنع الثغرة نفسها.

---

# Secure Cookie

إذا كانت:

```
Secure
```

فسيتم إرسالها فقط عبر HTTPS.

---

# SameSite Cookie

تحدد متى تُرسل الكوكي مع الطلبات القادمة من مواقع أخرى، وتساعد في تقليل مخاطر هجمات مثل CSRF.

---

# Local Storage

يخزن بيانات داخل المتصفح.

مثال

```
localStorage.setItem("name","Fares");
```

قراءة

```
localStorage.getItem("name");
```

لا يُرسل تلقائيًا مع كل طلب مثل الكوكيز.

---

# Session Storage

يشبه Local Storage، لكن البيانات تُحذف عند إغلاق التبويب.

---

# لماذا تحدث XSS؟

السبب الأساسي:

```
بيانات من المستخدم

↓

لا يتم التعامل معها بطريقة صحيحة

↓

تعرض داخل الصفحة

↓

المتصفح يعتبرها كودًا

↓

تنفيذ JavaScript
```

---

# مثال توضيحي

إذا أخذ الموقع قيمة البحث وأدخلها داخل الصفحة كما هي:

```
?search=Hello
```

فسيظهر:

```
Hello
```

لكن إذا كانت البيانات تحتوي على وسوم HTML أو JavaScript ولم تُعالج بشكل صحيح، فقد يفسرها المتصفح على أنها جزء من الصفحة بدلًا من عرضها كنص.

---

# دورة حياة ثغرة XSS

```
1- User Input

↓

2- Website Receives Data

↓

3- No Validation / No Proper Output Encoding

↓

4- Data Returned To Browser

↓

5- Browser Parses HTML

↓

6- Browser Executes JavaScript

↓

7- Impact Depends On Context
```
