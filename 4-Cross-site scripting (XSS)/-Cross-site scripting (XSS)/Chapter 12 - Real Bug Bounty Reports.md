
---
# مقدمة

تقارير Bug Bounty هي من أفضل مصادر التعلم.

لأنها تعرض:

- مشكلة حقيقية.
- طريقة اكتشافها.
- سبب وجودها.
- تأثيرها.
- وكيف تم إصلاحها.

---

# ما هو Bug Bounty Report؟

هو تقرير يكتبه الباحث الأمني بعد اكتشاف ثغرة.

يرسله إلى الشركة ويحتوي على كل المعلومات اللازمة لفهم المشكلة وإصلاحها.

---

# الهدف من قراءة التقارير

لا تقرأ التقرير لتنسخ الحل.

اقرأه لتتعلم:

- كيف فكر الباحث؟
- كيف اكتشف نقطة الإدخال؟
- لماذا كانت الثغرة موجودة؟
- كيف كان يمكن منعها؟

---

# مكونات التقرير

غالبًا ستجد:

```
Title

Summary

Severity

Affected Component

Description

Steps to Reproduce

Impact

Evidence

Suggested Fix
```

---

# 1. Title

عنوان مختصر يصف المشكلة.

مثال:

```
Reflected XSS in Search Function
```

العنوان وحده يخبرك:

- نوع الثغرة.
- مكانها.

---

# 2. Summary

ملخص سريع.

يجيب عن:

- ما المشكلة؟
- أين توجد؟
- ما تأثيرها؟

---

# 3. Severity

مدى خطورة الثغرة.

غالبًا يستخدم معيار:

```
CVSS
```

أو تصنيف داخلي للشركة:

```
Critical

High

Medium

Low

Informational
```

---

# 4. Affected Component

ما الجزء المتأثر؟

مثل:

- Search
- Login
- Profile
- Admin Panel
- API
- Chat

---

# 5. Description

أهم جزء في التقرير.

اشرح لنفسك:

- كيف تعمل الصفحة؟
- أين دخلت البيانات؟
- كيف انتقلت؟
- أين ظهرت؟

---

# 6. Steps to Reproduce

في التقارير الحقيقية ستجد خطوات إعادة إنتاج المشكلة.

أثناء الدراسة لا تحفظ الخطوات.

بل حلل:

```
Input

↓

Processing

↓

Output
```

---

# 7. Impact

هذا أهم جزء بعد الوصف.

اسأل:

لماذا تعتبر المشكلة خطيرة؟

مثال:

- تنفيذ JavaScript غير متوقع.
- سرقة جلسة المستخدم (إذا لم تكن هناك وسائل حماية مناسبة).
- تعديل محتوى الصفحة.
- تنفيذ إجراءات باسم المستخدم.

---

# 8. Evidence

قد يحتوي على:

- Screenshots
- HTTP Requests
- HTTP Responses
- Console Logs

استخدمها لفهم ما حدث.

---

# 9. Suggested Fix

لا تتجاهله.

بل اسأل:

كيف أصلحت الشركة المشكلة؟

غالبًا سترى:

- Input Validation
- Output Encoding
- Safe DOM APIs
- CSP
- تحسينات في معالجة البيانات

---

# طريقة تحليل أي تقرير

استخدم هذا النموذج:

```
1. اقرأ العنوان.

↓

2. افهم وظيفة الصفحة.

↓

3. حدد نقطة الإدخال.

↓

4. حدد نقطة الإخراج.

↓

5. حدد Context.

↓

6. تتبع Data Flow.

↓

7. افهم سبب المشكلة.

↓

8. اقرأ طريقة الإصلاح.

↓

9. اكتب الدرس المستفاد.
```

---

# لا تحفظ الـ Payload

الخطأ الشائع:

```
قرأ التقرير

↓

نسخ الـ Payload

↓

حفظه

↓

نسي كل شيء
```

```
قرأ التقرير

↓

فهم التطبيق

↓

حدد Context

↓

حلل Data Flow

↓

فهم سبب المشكلة
```
