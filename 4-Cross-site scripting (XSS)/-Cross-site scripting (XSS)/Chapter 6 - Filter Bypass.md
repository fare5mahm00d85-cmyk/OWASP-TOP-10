
--- 
# مقدمة

عندما يستقبل الموقع بيانات من المستخدم، فإنه غالبًا لا يرسلها مباشرة إلى الصفحة.

قبل ذلك قد تمر بعدة طبقات حماية.

الرسم التالي يوضح دورة البيانات:

```
User Input
     │
     ▼
Validation
     │
     ▼
Filtering
     │
     ▼
Sanitization
     │
     ▼
Output Encoding
     │
     ▼
Browser
```

---

# لماذا تستخدم المواقع Filters؟

الهدف ليس منع XSS فقط.

بل أيضًا:

- منع البيانات غير الصحيحة.
- حماية التطبيق.
- تحسين جودة المدخلات.
- تقليل المخاطر الأمنية.

---

# ما هو Filter؟

الـ Filter هو كود يقوم بفحص البيانات قبل استخدامها.

مثال بسيط:

```
Input

↓

Filter

↓

Accept أو Reject
```

---

# أنواع الفلاتر

```
Blacklist

Whitelist

Pattern Matching

Length Validation

Character Validation

Type Validation
```

---

# Blacklist

تعني:

> "امنع الأشياء المعروفة بأنها خطيرة."

مثال:

```
منع الكلمات:
<script>
javascript:
onerror
onclick
```

---

## المميزات

- سهل التنفيذ.
- مناسب في بعض الحالات البسيطة.

---

## العيوب

- من الصعب توقع كل الإدخالات الخطرة.
- يحتاج تحديثًا مستمرًا.
- قد يمنع بيانات صحيحة بالخطأ.

---

# Whitelist

تعني:

> "اسمح فقط بما أعرف أنه صحيح."

مثال:

إذا كان الحقل يقبل العمر.

المسموح فقط:

```
0-9
```

أي شيء آخر يتم رفضه.

---

## المميزات

- أكثر أمانًا.
- أوضح.
- أسهل في المراجعة.

---

## العيوب

- يحتاج تحديدًا دقيقًا لما هو مسموح.

---

# مقارنة

|Blacklist|Whitelist|
|---|---|
|تمنع الممنوع|تسمح بالمسموح|
|أصعب في الصيانة|أكثر أمانًا غالبًا|
|قد تفوت حالات|تقلل الاحتمالات غير المتوقعة|

---

# Validation

Validation تعني:

> هل البيانات مطابقة لما أتوقعه؟

مثال:

البريد الإلكتروني.

هل هو بصيغة صحيحة؟

---

# Type Validation

مثال

```
Age
```

يجب أن يكون رقمًا.

---

# Length Validation

مثال

اسم المستخدم:

من 3 إلى 20 حرفًا.

---

# Character Validation

مثال

يسمح فقط بـ

```
A-Z

a-z

0-9
```

---

# Pattern Validation

يعتمد غالبًا على Regular Expressions.

مثال:

التحقق من أن البريد الإلكتروني أو رقم الهاتف يطابق نمطًا معينًا.

---

# Sanitization

الـ Sanitization لا يمنع كل شيء.

بل يحاول إزالة أو تعديل العناصر غير المسموح بها مع الحفاظ على المحتوى المقبول.

مثال:

إذا كان الموقع يسمح بتنسيق النص، فقد يسمح بعناصر مثل:

```
<b>
<i>
```

ويزيل العناصر أو الخصائص الخطرة.

---

# Output Encoding

هذه من أهم وسائل الحماية.

الفكرة:

بدلًا من إرسال البيانات كما هي،

يتم ترميزها بما يناسب مكان عرضها.

---

# لماذا Output Encoding مهم؟

لأن المتصفح يفسر HTML.

لكن إذا تم ترميز الأحرف الخاصة،

سيعرضها كنص.

---

# Context Matters

أكبر خطأ يقع فيه المطور:

استخدام نفس طريقة Encoding في كل مكان.

الحقيقة:

لكل Context طريقة مناسبة.

```
HTML Context

↓

HTML Encoding

----------------

Attribute Context

↓

Attribute Encoding

----------------

JavaScript Context

↓

JavaScript String Encoding

----------------

URL Context

↓

URL Encoding
```

---

# Canonicalization

تعني:

تحويل البيانات إلى شكل موحد قبل التحقق منها.

مثال:

قد تمثل نفس البيانات بأكثر من طريقة ترميز.

إذا لم يتم توحيد التمثيل أولًا، قد تصبح عملية الفحص غير دقيقة.

---

# Normalization

تشبه Canonicalization.

الهدف:

جعل البيانات في شكل ثابت يسهل التعامل معه.

---

# لماذا يجب فهم Browser Parsing؟

لأن المتصفح لا يقرأ الصفحة كما يقرأها الإنسان.

هو يمر بمراحل:

```
HTML

↓

Tokenizer

↓

Parser

↓

DOM

↓

Rendering
```

وأي خطأ في فهم هذه المراحل يؤدي إلى أخطاء أمنية.

---

# Defense in Depth

الحماية لا تعتمد على طبقة واحدة.

أفضل تصميم:

```
Validation

↓

Sanitization

↓

Output Encoding

↓

Content Security Policy

↓

HttpOnly Cookies

↓

Code Review
```

إذا فشلت طبقة،

تبقى الطبقات الأخرى موجودة.

---

# Content Security Policy (CSP)

طبقة إضافية.

وظيفتها:

تقليل أثر XSS إذا حدثت.

وسنشرحها بالتفصيل في Chapter 10.

---

# HttpOnly

إذا كانت Cookie تحمل:

```
HttpOnly
```

فلن تستطيع JavaScript قراءتها.

وهذا يقلل من بعض آثار XSS.

---

# Secure Cookie

تُرسل فقط عبر HTTPS.

---

# SameSite

تقلل مخاطر بعض الهجمات بين المواقع مثل CSRF.

---

# أخطاء شائعة عند المطورين

❌ الاعتماد على Blacklist فقط.

❌ عدم استخدام Output Encoding.

❌ استخدام نفس Encoding لكل Context.

❌ الاعتقاد أن Sanitization وحدها تكفي.

❌ نسيان تفعيل CSP.

---

# كيف تفكر كـ Penetration Tester؟

بدلًا من السؤال:

> "كيف أتجاوز الفلتر؟"

اسأل:

- أين يتم التحقق من البيانات؟
- هل يوجد Validation؟
- هل يوجد Sanitization؟
- هل يتم استخدام Output Encoding؟
- هل يتناسب مع الـ Context؟
- هل توجد طبقات حماية إضافية مثل CSP وHttpOnly؟

هذا التفكير يساعدك على فهم سبب نجاح أو فشل الاختبارات داخل بيئات التدريب.
